# Настройка OpenAL Soft в IX-Ray

Эта памятка относится к OpenAL Soft 1.23.1, который используется текущей сборкой IX-Ray. Версия подтверждается файлом `build/bin/RelWithDebInfo/OpenAL32.dll` и настройкой зависимости в `cmake/modules/OpenalSoft.cmake`.

Основной конфиг для конкретной сборки:

```text
build/bin/RelWithDebInfo/alsoft.ini
```

OpenAL Soft читает его при запуске процесса. После изменения параметров игру нужно полностью закрыть и запустить заново. Команда `snd_restart` в этой ветке IX-Ray перезапускает звуковой кэш и окружение, но не перечитывает `alsoft.ini` и не пересоздаёт устройство OpenAL.

## Коротко: с чего начать

1. Сделать копию исходного `alsoft.ini`.
2. Менять за один тест только одну группу параметров.
3. Полностью перезапускать игру после каждого изменения.
4. Сначала подобрать `period_size` и `periods`, затем HRTF и ресемплер, и только потом громкость реверберации.
5. Оценивать не только качество позиционирования, но и треск, выпадения звука, задержку выстрелов и нагрузку в насыщенных сценах.

Для наушников разумная отправная точка:

```ini
[general]
drivers = wasapi,
channels = stereo
sample-type = float32
frequency = 48000
period_size = 512
periods = 3
stereo-mode = headphones
stereo-encoding = hrtf
hrtf-mode = full
resampler = bsinc24
sources = 1024
output-limiter = true
volume-adjust = 0

[reverb]
boost = 0
```

Запятая после `wasapi` разрешает резервный переход на другие доступные бэкенды, если WASAPI не откроется. Значение `drivers = wasapi` без запятой запрещает такой переход.

Если появляются щелчки или пропуски, сначала использовать:

```ini
period_size = 1024
periods = 3
```

Если этого недостаточно:

```ini
period_size = 1024
periods = 4
hrtf-mode = ambi2
resampler = cubic
```

Это увеличивает запас аудиобуфера и снижает стоимость пространственной обработки, но повышает задержку и немного ухудшает точность HRTF и ресемплинга.

## Сравнение настроек: по умолчанию и сейчас

В таблице «до» означает эффективное штатное поведение OpenAL Soft 1.23.1 без переопределений, а «после» — текущий `build/bin/RelWithDebInfo/alsoft.ini`. Это не простое сравнение текста шаблонов: учтены значения из кода 1.23.1, параметры, зависящие от формата вывода, и то, что IX-Ray создаёт контекст без собственного списка ALC-атрибутов.

| Параметр | До — OpenAL Soft 1.23.1 по умолчанию | После — текущий `alsoft.ini` | Что изменилось |
| --- | --- | --- | --- |
| `drivers` | Все скомпилированные бэкенды; на Windows первым пробуется WASAPI, затем доступны резервные варианты | `wasapi,` | Приоритет фактически тот же, но WASAPI выбран явно; запятая сохраняет резервный переход. |
| `channels` | Автоопределение системного формата, при неудаче — stereo | Не задан | Без изменений. Если Windows сообщает 5.1/7.1, HRTF не гарантирован; для наушников надёжнее явно задать `channels = stereo`. |
| `sample-type` | `float32` | `float32` | Без изменения качества/формата; текущее значение просто фиксирует штатный формат. |
| `frequency` | Определение по устройству, резервное значение 48000 Гц | `48000` | Частота 48 кГц теперь запрашивается принудительно. При другом системном режиме возможен дополнительный ресемплинг. |
| `period_size` | 960 кадров при 48 кГц, то есть 20 мс | 512 кадров, то есть 10,67 мс | Микшер обновляется почти вдвое чаще; внутренняя задержка меньше, нагрузка и чувствительность к зависаниям CPU выше. |
| `periods` | `3` | `3` | Без изменений. |
| Номинальный mix-ahead | 2880 кадров, около 60 мс | 1536 кадров, около 32 мс | Внутренний запас сокращён на 28 мс, примерно на 46,7%. Реальная задержка также включает WASAPI, драйвер и устройство. |
| `stereo-mode` | `auto` | `headphones` | Стереоустройство принудительно считается наушниками. |
| `stereo-encoding` | Явно не задан: для обнаруженных наушников OpenAL Soft может автоматически выбрать HRTF, иначе используется обычное стереопанорамирование | `hrtf` | Бинауральное HRTF-позиционирование теперь запрошено явно и больше не зависит от автоопределения типа стереоустройства. Закомментированная подсказка `basic` в sample-файле не является активной настройкой. |
| `hrtf` | Явно не задан (`auto`-поведение); IX-Ray сам HRTF не запрашивает | `true` | HRTF дополнительно форсируется старым ключом. Это работает, но дублирует `stereo-encoding = hrtf` и выдаёт предупреждение об устаревшем параметре. |
| `hrtf-mode` | `full`, если HRTF вообще включён | `full` | Сам режим не изменён, но теперь реально используется при стереовыходе: максимальная точность и максимальная нагрузка HRTF. |
| `default-hrtf` | Первый доступный набор, если приложение не выбрало другой | Пустая строка | Локально результат тот же, но пустая строка очищает возможный выбор из `%AppData%\alsoft.ini`. |
| `cf_level` | `0`, crossfeed выключен | `2` | Значение задано, но при активном HRTF игнорируется. |
| `resampler` | `cubic` | `bsinc24` | Повышено качество изменения частоты/тона и нагрузка микшера. |
| `sources` | `256` | `1024` | Лимит увеличен в четыре раза. Это позволяет IX-Ray создать запрашиваемые 992 звуковые цели вместо остановки примерно на 256. |
| `output-limiter` | При `float32` без явного ключа фактически выключен | Не задан; при текущем `float32` фактически выключен | Без изменений. Из-за `reverb/boost = 2` явное `output-limiter = true` может быть полезно против пиков. |
| `dither` / `dither-depth` | Dither разрешён, но при `float32` и глубине `0` фактически не применяется | Не заданы; фактически не применяется | Без изменений. |
| `volume-adjust` | `0` дБ | `0` дБ | Без изменений. |
| `decoder/hq-mode` | `true` | `false` | Высококачественный амбисонический декодер отключён. Для stereo + `hrtf-mode = full` почти не влияет; важнее для многоканального/амбисонического декодирования. |
| `reverb/boost` | `0` дБ | `+2` дБ | Игровой EFX/EAX Reverb усилен приблизительно в 1,26 раза по амплитуде. |

Главный итог: текущий конфиг включает HRTF максимального качества, переводит ресемплер с `cubic` на `bsinc24`, сокращает номинальный внутренний запас с 60 до 32 мс и увеличивает лимит источников с 256 до 1024. В обмен растёт нагрузка на звуковой поток и уменьшается запас против underrun.

Строки вида `default-hrtf =`, `quad =` или `nfc-ref-delay =` не задают отдельное пустое значение. Парсер 1.23.1 удаляет ранее заданное значение этого ключа, поэтому такие строки могут очищать настройку из `%AppData%\alsoft.ini`, но сами ничего не включают.

Пустые секции `[pulse]`, `[alsa]`, `[oss]`, `[jack]`, `[dsound]` и другие также ничего не меняют.

## Как считать `period_size`

`period_size` — количество sample frames на одно обновление микшера, а не время в миллисекундах. Для обычного PCM один frame содержит по одному сэмплу каждого выходного канала.

Приближённые формулы:

```text
период, мс = period_size / frequency * 1000
буфер, мс  = period_size * periods / frequency * 1000
```

Для 48 кГц:

| `period_size` | `periods` | Один период | Внутренний запас |
| ---: | ---: | ---: | ---: |
| 64 | 3 | 1,33 мс | 4,00 мс |
| 256 | 3 | 5,33 мс | 16,00 мс |
| 512 | 3 | 10,67 мс | 32,00 мс |
| 960 | 3 | 20,00 мс | 60,00 мс |
| 1024 | 3 | 21,33 мс | 64,00 мс |
| 1024 | 4 | 21,33 мс | 85,33 мс |

Это не полная задержка от события до уха. Дополнительно участвуют очередь WASAPI, Windows Audio Engine, драйвер и собственный буфер устройства.

OpenAL Soft 1.23.1 по умолчанию использует 960 кадров и 3 периода при 48 кГц. Текущие 512 × 3 дают около 32 мс номинального внутреннего запаса. Значения 256–512 подходят для экспериментов с низкой задержкой, а 960–1024 обычно дают более устойчивое воспроизведение. Минимум 64 следует использовать только после проверки на целевой системе: он резко увеличивает частоту пробуждений потока микшера и риск underrun.

## Формат и порядок загрузки конфига

На Windows конфиги загружаются в таком порядке:

1. `%AppData%\alsoft.ini`;
2. `alsoft.ini` рядом с исполняемым файлом;
3. дополнительный файл из переменной окружения `ALSOFT_CONF`.

Более позднее значение того же ключа заменяет более раннее. Поэтому конфиг рядом с `xrEngine.exe` перекрывает пользовательский `%AppData%\alsoft.ini`, а `ALSOFT_CONF` перекрывает оба.

Правила синтаксиса:

- комментарий начинается с `#`;
- `;` не является комментарием для парсера 1.23.1;
- имена ключей и секций следует считать чувствительными к регистру;
- повторяющийся ключ получает последнее непустое значение;
- пустое `key =` удаляет значение, полученное из ранее загруженного файла;
- значения разрешено заключать в одинарные или двойные кавычки;
- в значениях подставляются переменные окружения вида `$NAME`, а `$$` означает буквальный знак `$`;
- специфичная для устройства секция записывается как `[Имя устройства]`, а для бэкенда — как `[wasapi/Имя устройства]`.

## Основные параметры `[general]`

### Устройство, каналы и формат

| Параметр | Что меняет | Практическая рекомендация |
| --- | --- | --- |
| `drivers` | Список и порядок звуковых бэкендов. На Windows актуальны `wasapi`, `dsound`, `winmm`; `null` отключает реальный вывод, `wave` пишет файл. | Оставить пустым или использовать `wasapi,`. `wasapi` без запятой — только для диагностики. Старое имя `mmdevapi` пока преобразуется в `wasapi`, но новое имя предпочтительнее. |
| `channels` | Запрашиваемая конфигурация: `mono`, `stereo`, `quad`, `surround51`, `surround61`, `surround71`, `surround714`, `surround3d71`, `ambi1`, `ambi2`, `ambi3`. | Для HRTF явно задать `stereo`. Для реальных 5.1/7.1 сначала правильно настроить Windows и обычно оставить ключ незаданным. |
| `sample-type` | Формат выхода: 8/16/32-bit signed или unsigned integer либо `float32`. Внутренний микс всегда `float32`. | Обычно `float32` или отсутствие переопределения. `int32` не улучшает исходные Ogg-звуки, а только добавляет финальное преобразование. |
| `frequency` | Частота микширования и запрашиваемая частота устройства, 8000–192000 Гц. | `48000`. Имеет смысл совпадать с режимом Windows, чтобы избежать дополнительного ресемплинга. |
| `period_size` | Размер одного обновления микшера в кадрах, допустимо 64–8192. Меньше — ниже задержка, но больше пробуждений CPU и риск щелчков. | Начать с `512`; при проблемах перейти на `960` или `1024`. |
| `periods` | Число периодов в очереди, допустимо 2–16. Больше — надёжнее под нагрузкой, но выше задержка. | Обычно `3`; для нестабильного вывода `4`. |
| `stereo-mode` | Подсказывает, что стереоустройство является `headphones`, `speakers` или должно определяться автоматически (`auto`). | Наушники — `headphones`, колонки — `speakers`. |
| `ambi-format` | Порядок и нормализация каналов для `ambi*`: `fuma`, `acn+fuma`, `ambix`/`acn+sn3d`, `acn+n3d`. | Не менять для обычных наушников и колонок. Нужен только для вывода амбисонического потока во внешний декодер. |

### HRTF, стерео и позиционирование

| Параметр | Что меняет | Практическая рекомендация |
| --- | --- | --- |
| `stereo-encoding` | Способ построения стерео: `basic`, `uhj` или `hrtf`. | Для наушников — `hrtf`; для обычных стереоколонок — `basic`. Это замена устаревшему ключу `hrtf`. |
| `hrtf` | Старый переключатель `true`/`false`/`auto`. | Удалить после перехода на `stereo-encoding`. Не держать оба параметра без необходимости. |
| `hrtf-mode` | `full` фильтрует каждый источник отдельно; `ambi1`, `ambi2`, `ambi3` сначала смешивают источники в амбисоническую шину соответствующего порядка. | `full` — лучшая локализация; `ambi2` — хороший компромисс; `ambi1` — минимальная нагрузка и наиболее размытое направление. |
| `hrtf-size` | Ограничивает длину импульсной характеристики HRTF. `0` использует полный размер набора. | Оставить `0` или не задавать. Уменьшать только после доказанного дефицита CPU. |
| `default-hrtf` | Выбирает набор HRTF по его отображаемому имени, а не имени `.mhr`-файла. | Оставить незаданным, пока нужное имя не подтверждено логом OpenAL Soft. |
| `hrtf-paths` | Список каталогов с `.mhr`. Завершающая запятая сохраняет также стандартные пути поиска. На Windows стандартный пользовательский путь — `%AppData%\openal\hrtf`. | Для пользовательского набора использовать абсолютный путь и завершающую запятую, если нужны также встроенные/стандартные наборы. |
| `cf_level` | Crossfeed слегка подмешивает левый канал в правый и наоборот, имитируя прослушивание колонок в наушниках. Значения 1–6 задают характер фильтра. | Использовать только при `stereo-encoding = basic`. При HRTF не действует. |
| `front-stablizer` | Стабилизирует фронтальный образ через центральный канал. Орфография ключа с `stablizer` намеренная. | Имеет смысл только для конфигураций с Front Left, Front Right и Front Center. На стерео и HRTF не действует. |
| `stereo-encoding = uhj` | Кодирует часть окружающей сцены в совместимое двухканальное UHJ-стерео. | Нужно только для UHJ-декодера или осознанного эксперимента; для обычных наушников HRTF точнее. |

### Качество, нагрузка и количество звуков

| Параметр | Что меняет | Практическая рекомендация |
| --- | --- | --- |
| `resampler` | Качество изменения частоты/тона источников: `point`, `linear`, `cubic`, `bsinc12`, `fast_bsinc12`, `bsinc24`, `fast_bsinc24`. | `bsinc24` — максимум качества; `cubic` — лёгкий и хороший базовый вариант; `fast_bsinc12` — промежуточный вариант. |
| `sources` | Максимум создаваемых источников OpenAL. Меньшее число ограничивает количество одновременно обслуживаемых IX-Ray целей. | Для этой ветки оставить `1024`: движок запрашивает до 992 целей. Снижать до 512/256 только как осознанный компромисс при проблемах с CPU или памятью. |
| `slots` | Заявленный лимит Auxiliary Effect Slots. Слот с активным эффектом потребляет CPU даже без посылов. | IX-Ray создаёт один игровой слот реверберации. В исходниках включённой 1.23.1 лимит устройства фиксирован в 64, а чтение этого ключа не обнаружено, поэтому не следует рассчитывать на него как на рабочий ограничитель. |
| `sends` | Максимум вспомогательных посылов на источник; может только уменьшить доступный максимум. | IX-Ray использует send 0 для игрового ревербератора. Не задавать `0`, иначе реверберация не сможет подключиться. Повышение сверх внутреннего максимума ничего не даёт. |
| `disable-cpu-exts` | Запрещает SIMD-оптимизации `sse`, `sse2`, `sse3`, `sse4.1`, `neon` или все сразу (`all`). | Не задавать. Используется для диагностики ошибок CPU/компилятора, а не для обычной настройки качества. |
| `rt-prio` | Приоритет реального времени для потока микшера, если бэкенд его использует. Ноль и отрицательные значения отключают. | Оставить по умолчанию. Завышенный realtime-приоритет способен мешать другим потокам и усложнять зависания. |

### Финальная громкость и защита от искажений

| Параметр | Что меняет | Практическая рекомендация |
| --- | --- | --- |
| `output-limiter` | Ограничивает пики перед выводом, уменьшая цифровой clipping. Добавляет небольшую обработку и look-ahead задержку. | `true`, особенно при `int16`/`int32`, положительном `volume-adjust` или `reverb/boost`. |
| `dither` | Добавляет очень тихий шум вместо коррелированных ошибок квантования. | Нужен в основном для 8- и 16-битного целого выхода. Для `float32` и `int32` при стандартной глубине практически не нужен. |
| `dither-depth` | Целевая глубина dithering, максимум 24. Ноль выбирает глубину выходного формата; для `int32` и `float32` это отключает dithering. | Не задавать либо `0`. |
| `volume-adjust` | Общее усиление в децибелах, ограничивается диапазоном −24…+24 дБ. +6 дБ приблизительно удваивает амплитуду, −6 дБ уменьшает её вдвое. | Держать `0`; положительные значения повышают риск срабатывания лимитера и изменения динамики. |
| `reverb/boost` | Глобальное усиление только EFX Reverb/EAX Reverb, −24…+24 дБ. | `0` — нейтрально. Текущие `+2` дБ допустимы, если усиленная реверберация выбрана намеренно. |

### Эффекты и диагностика

| Параметр | Что меняет | Практическая рекомендация |
| --- | --- | --- |
| `excludefx` | Запрещает перечисленные EFX-эффекты. | Не исключать `eaxreverb` и `reverb`: IX-Ray использует EAX Reverb. |
| `default-reverb` | Автоматически назначает всем источникам стандартный пресет на send 0, пока приложение не назначит свой. | Для IX-Ray оставить незаданным: движок сам загружает игровые параметры окружения. |
| `trap-al-error` | Вызывает breakpoint exception на ошибке AL. | Только под отладчиком. Иначе ошибка может выглядеть как аварийное завершение. |
| `trap-alc-error` | То же для ошибок устройства и контекста ALC. | Только под отладчиком. |

## Параметры `[decoder]`

Эта секция в основном относится к реальным многоканальным колонкам и амбисоническому выводу. Для стереонаушников с `hrtf-mode = full` большинство параметров не участвует.

| Параметр | Что меняет |
| --- | --- |
| `hq-mode` | Включает высококачественный, в том числе частотно-зависимый, амбисонический декодер. Повышает качество многоканального вывода и нагрузку. |
| `distance-comp` | Компенсирует разные расстояния от слушателя до колонок задержкой и ослаблением. Для точной работы нужны корректные расстояния в пользовательском decoder-файле. |
| `nfc` | Near-field control: корректирует ближнее поле низких частот. Для HRTF требует `hrtf-mode = ambi1/2/3`; при `full` не применяется. |
| `speaker-dist` | Расстояние до колонок в метрах для NFC, если оно не задано decoder-файлом. Диапазон 0,1–10 м. |
| `quad`, `surround51`, `surround61`, `surround71`, `surround3d71` | Пути к пользовательским конфигурациям амбисонического декодера для соответствующих схем колонок. |

Ключ `nfc-ref-delay` присутствует в приложенном старом шаблоне, но отсутствует в конфигурации и коде OpenAL Soft 1.23.1 этой сборки. Пустая строка сейчас ничего не делает; для актуальной настройки используются `nfc` и `speaker-dist`.

## Бэкенды

### Windows

| Секция/бэкенд | Назначение |
| --- | --- |
| `wasapi` / `[wasapi]` | Основной современный Windows-бэкенд. В этой сборке включён и стоит раньше DirectSound/WinMM. Обычно лучший выбор. |
| `dsound` / `[dsound]` | Старый DirectSound-бэкенд для совместимости. Может иметь другую задержку и поведение устройства. |
| `winmm` / `[winmm]` | Ещё более старый Windows Multimedia API; использовать как аварийный вариант. |
| `[mmdevapi]` | Старое имя. В списке `drivers` 1.23.1 ещё преобразует `mmdevapi` в `wasapi`, но секцию настроек следует называть `[wasapi]`. В приложенном файле `[mmdevapi]` пуста и ни на что не влияет. |

Наиболее безопасная запись:

```ini
drivers = wasapi,
```

Только WASAPI, без резервного бэкенда:

```ini
drivers = wasapi
```

Все доступные бэкенды, кроме DirectSound:

```ini
drivers = -dsound,
```

### Linux и другие системы

Эти секции не влияют на текущий Windows-запуск, но находятся в полном шаблоне:

| Секция | Основные параметры |
| --- | --- |
| `[pulse]` | `spawn-server` разрешает запуск PulseAudio; `allow-moves` разрешает серверу перемещать поток между устройствами; `fix-rate` подгоняет частоту микшера под частоту устройства и помогает избежать второго ресемплинга. |
| `[alsa]` | `device`/`capture` выбирают устройство; `device-prefix`, `device-prefix-*`, `capture-prefix` и `capture-prefix-*` задают общие либо специфичные для карты/устройства префиксы обнаружения; `mmap` пробует mmap-режим; `allow-resampler` разрешает дополнительный ресемплер ALSA. |
| `[oss]` | `device` и `capture` задают устройства OSS. |
| `[solaris]` | `device` задаёт устройство Solaris audio. |
| `[qsa]` | Настройки QNX QSA; в текущем шаблоне параметров нет. |
| `[jack]` | `spawn-server` запускает JACK при необходимости; `buffer-size` задаёт внутренний запас, округляемый до степени двойки. В 1.23.1 также есть `rt-mix` и `connect-ports`. |
| `[port]` | `device` и `capture` выбирают индексы PortAudio; отрицательное значение означает устройство по умолчанию. |

### Вывод в WAV

Бэкенд `[wave]` предназначен не для обычной игры, а для записи выхода в файл:

| Параметр | Что меняет |
| --- | --- |
| `file` | Имя WAV-файла. Существующий файл перезаписывается без подтверждения. |
| `bformat` | Записывает first-order ambisonic B-Format вместо обычного mono/stereo/multichannel WAV. |

Не включать `drivers = wave` с путём к ценному существующему файлу.

### Реальные 5.1/7.1 колонки

Сначала выбрать правильную конфигурацию устройства в Windows. Затем не форсировать `channels`, чтобы OpenAL Soft мог получить системный формат, либо явно задать `surround51`/`surround71`, если автоопределение ошибается.

```ini
[general]
drivers = wasapi,
sample-type = float32
frequency = 48000
period_size = 960
periods = 3
stereo-mode = speakers
stereo-encoding = basic
front-stablizer = true
resampler = bsinc24
sources = 1024
output-limiter = true
volume-adjust = 0

[decoder]
hq-mode = true

[reverb]
boost = 0
```

`front-stablizer` следует сравнить в игре в положениях, где источник находится строго спереди: эффект зависит от расстановки и акустики комнаты.

## Диагностика

Для подробного лога OpenAL Soft перед запуском процесса можно временно задать переменные окружения:

```powershell
$env:ALSOFT_LOGLEVEL = '3'
$env:ALSOFT_LOGFILE = 'C:\Temp\ixray-openal.log'
```

Затем запустить игру из того же процесса/терминала. Лог-файл при инициализации очищается. После диагностики переменные лучше удалить:

```powershell
Remove-Item Env:ALSOFT_LOGLEVEL
Remove-Item Env:ALSOFT_LOGFILE
```

В логе полезно проверить:

- какой конфиг был загружен;
- какой бэкенд и устройство открыты;
- фактические частоту, каналы, sample type, update size и buffer size;
- включён ли HRTF и какой набор выбран;
- сколько источников, effect slots и sends доступно;
- нет ли предупреждений об устаревших или неизвестных параметрах.

### Если звук трещит или пропадает

1. Увеличить `period_size` до 512, затем до 960/1024.
2. Увеличить `periods` с 3 до 4.
3. Заменить `hrtf-mode = full` на `ambi2`.
4. Заменить `bsinc24` на `cubic` или `fast_bsinc12`.
5. Убедиться, что частота Windows и `frequency` совпадают, обычно 48000 Гц.
6. Временно проверить `drivers = wasapi` и отдельно `drivers = dsound`, чтобы отличить проблему бэкенда от нагрузки микшера.

### Если направление звука определяется плохо

1. Для наушников проверить `channels = stereo`, `stereo-mode = headphones`, `stereo-encoding = hrtf`.
2. Убедиться, что Windows не добавляет поверх HRTF ещё одну виртуализацию: Windows Sonic, Dolby Atmos, DTS Headphone:X или фирменный 7.1-режим гарнитуры.
3. Сравнить разные HRTF-наборы, выбирая их через `default-hrtf` по имени из лога.
4. Сравнить `hrtf-mode = full` и `ambi2`.
5. Не пытаться исправить HRTF параметром `cf_level`: при HRTF он не работает.

### Если реверберация слишком сильная или клипует

1. Вернуть `[reverb] boost = 0`.
2. Оставить `volume-adjust = 0`.
3. Включить `output-limiter = true`.
4. Не использовать `default-reverb`: IX-Ray назначает собственный EFX-слот окружения.
5. Проверить отдельно игровую команду `snd_efx`, потому что она управляет использованием EFX со стороны движка, а не конфигом OpenAL Soft.

## Особенности именно этой сборки IX-Ray

- Движок открывает устройство и создаёт контекст без собственного списка ALC-атрибутов, поэтому `alsoft.ini` определяет частоту, формат, каналы, HRTF и размеры буферов, если бэкенд способен их принять.
- `snd_device` сохраняет выбранный IX-Ray идентификатор устройства для инициализации звука, но сам по себе не переключает уже открытое устройство и не перечитывает конфиг OpenAL Soft.
- `snd_restart` не закрывает OpenAL-устройство и не перечитывает `alsoft.ini`.
- IX-Ray по умолчанию запрашивает до 992 звуковых целей; поэтому `sources = 1024` в исходном конфиге имеет практический смысл.
- Движок создаёт один Auxiliary Effect Slot и подключает его как send 0 к игровым 3D-источникам, кроме источников, помеченных как intro. Параметр `[reverb] boost` поэтому действительно меняет игровой EFX-ревербератор.
- Файл `soft_oal.dll` версии 1.21.1, находящийся рядом, не становится библиотекой OpenAL только из-за присутствия. Текущий бинарник загружает `OpenAL32.dll` версии 1.23.1.
