# Настройка меткости НПС

> [!IMPORTANT]
> Памятка описывает фактическое поведение текущей ветки IX-Ray и текущие значения `gamedata/configs/creatures/m_stalker.ltx`. Она относится к обычным НПС, наследующим секцию `[stalker]`. Секция `[stalker_zombied]` в `m_stalker_zombied.ltx` переопределяет все восемь параметров разброса.

## Коротко

- Чем меньше `disp_*`, тем точнее НПС.
- Значения `disp_*` задаются в градусах и описывают вклад самого стрелка, а не полный разброс оружия.
- Движок умножает этот вклад на коэффициент ранга и прибавляет его к разбросу оружия.
- `fire_queue_params` меняет длину очередей и паузы, но не направление отдельной пули.
- `eye_fov`, `eye_range` и секции зрения влияют на обнаружение цели, а не на разброс выстрела.
- В одиночной игре попадание по актору дополнительно проходит проверку `hit_probability_gd_*` оружия. Это отдельный механизм, не входящий в `disp_*`.

## Какие параметры используются

Текущая секция `[stalker]` содержит:

```ini
;---FIRE DISPERSIONS--------------------------------------------------
disp_walk_stand          = 3
disp_walk_crouch         = 2
disp_run_stand           = 5
disp_run_crouch          = 4
disp_stand_stand         = 3
disp_stand_crouch        = 2
disp_stand_stand_zoom    = 1
disp_stand_crouch_zoom   = 1
```

При загрузке НПС движок читает все восемь значений как обязательные `float`. Итоговый выбор зависит от движения и положения тела.

| Состояние НПС | Фактически выбранный параметр | Текущее значение |
| --- | --- | ---: |
| Идёт стоя | `disp_walk_stand` | 3° |
| Идёт пригнувшись | `disp_walk_crouch` | 2° |
| Бежит стоя | `disp_run_stand` | 5° |
| Бежит пригнувшись | `disp_run_crouch` | 4° |
| Не движется стоя, `zoom_state() == true` | `disp_stand_stand` | 3° |
| Не движется стоя, `zoom_state() == false` | `disp_stand_stand_zoom` | 1° |
| Не движется пригнувшись, `zoom_state() == true` | `disp_stand_crouch` | 2° |
| Не движется пригнувшись, `zoom_state() == false` | `disp_stand_crouch_zoom` | 1° |

Для ходьбы и бега соответствующая ветвь используется, пока путь движения не завершён. После завершения пути движок переходит к выбору одного из четырёх параметров стоящего НПС.

### Особенность параметров `*_zoom`

В текущей реализации `CAI_Stalker::GetWeaponAccuracy()` названия и условия для неподвижного НПС не совпадают:

- при `zoom_state() == true` выбирается параметр **без** суффикса `_zoom`;
- при `zoom_state() == false` выбирается параметр **с** суффиксом `_zoom`.

`zoom_state()` возвращает `true` для состояний прицеливания, готовности к стрельбе, стрельбы и части состояний перезарядки. Поэтому при настройке текущего движка фактическую меткость прицелившегося НПС задают `disp_stand_stand` и `disp_stand_crouch`, а не параметры `*_zoom`.

Это описание текущего поведения, а не рекомендация закреплять его в новых реализациях. Если условия в C++ будут исправлены, смысл двух пар параметров поменяется местами.

На сетевом клиенте `GetWeaponAccuracy()` сразу возвращает `disp_stand_stand` без коэффициента ранга и без выбора состояния. Описанная ниже формула относится к серверному расчёту, который используется в одиночной игре; сетевое поведение требует отдельной проверки.

## Влияние ранга

К выбранному значению `disp_*` применяется коэффициент ранга из секции `[ranks_properties]` файла `gamedata/configs/creatures/game_relations.ltx`:

```ini
dispersion_novice_k      = 1.0
dispersion_experienced_k = 0.05
```

Движок ограничивает ранг диапазоном `0..1000` и вычисляет линейную интерполяцию:

```text
K_rank = 1.0 + (0.05 - 1.0) × clamp(rank, 0, 1000) / 1000
D_npc  = disp_state × K_rank
```

| Ранг | `K_rank` | Вклад для `disp_stand_stand = 3` |
| ---: | ---: | ---: |
| 0 | 1,0000 | 3,000° |
| 30 | 0,9715 | 2,9145° |
| 60 | 0,9430 | 2,829° |
| 90 | 0,9145 | 2,7435° |
| 100 | 0,9050 | 2,715° |
| 300 | 0,7150 | 2,145° |
| 600 | 0,4300 | 1,290° |
| 900 | 0,1450 | 0,435° |
| 1000 | 0,0500 | 0,150° |

В текущих XML-профилях `gamedata/configs/gameplay/character_desc_*.xml` фиксированные значения `<rank>` находятся в диапазоне `0..100`. При таких профилях действующий коэффициент меняется только от `1,0` до `0,905`; значение `dispersion_experienced_k = 0.05` полностью достигается лишь при ранге `1000`.

Если требуется заметно разделить меткость обычных профилей с рангами `0..100`, одной заменой `dispersion_experienced_k` это сделать неудобно: формула всё равно использует делитель `1000`. Безопаснее либо согласованно перевести ранги на шкалу `0..1000`, либо изменить нормализацию в C++ и повторно сбалансировать все системы, использующие ранг.

## Полный угловой разброс

В обычном пути стрельбы полный разброс складывается из двух частей:

```text
D_total = D_weapon + D_npc

D_weapon = fire_dispersion_base
         × silencer_dispersion_k
         × ammo_k_disp
         × (1 + fire_dispersion_condition_factor × (1 - condition))
         × owner_fire_dispersion_modifier

D_npc = disp_state × K_rank
```

Все величины складываются движком в радианах, но параметры `fire_dispersion_base` оружия и `disp_*` НПС записываются в LTX в градусах. Поэтому для ручного расчёта их можно складывать как градусы после применения коэффициентов.

Пример для текущего `wpn_ak74` в идеальном состоянии, с патроном `k_disp = 1`, без меняющего разброс глушителя и с нейтральным модификатором владельца:

```text
Ранг 0, НПС целится стоя:
D_total = 0,33° + 3° × 1,0 = 3,33°

Ранг 100, НПС целится стоя:
D_total = 0,33° + 3° × 0,905 = 3,045°
```

Генератор направления использует `D_total / 3` как параметр распределения и ограничивает отклонение диапазоном от `-D_total` до `D_total`. Это не означает, что каждая пуля уходит к краю конуса: малые отклонения встречаются чаще.

Для грубой оценки предельного линейного отклонения на дистанции `L`:

```text
R_max ≈ L × tan(D_total)
```

Например, `3°` дают предельный радиус около `1,57 м` на дистанции `30 м`. Это только геометрическая оценка разброса: реальное попадание также зависит от направления прицеливания НПС, движения цели, баллистики, укрытий и проверки вероятности попадания.

### Исключение для первых пуль очереди

Если у оружия задан `base_dispersioned_bullets_count`, первые настроенные пули очереди используют только базовый разброс оружия и не получают добавку `D_npc`. В текущем наборе конфигов такой режим задан у `wpn_abakan` для первых двух пуль. Поэтому изменение `m_stalker.ltx` не обязано менять их группирование.

## Дополнительная вероятность попадания по актору

В одиночной игре после геометрического пересечения пули со сферой актора движок может отклонить попадание отдельной вероятностной проверкой. Для вооружённого НПС используются параметры оружия:

```ini
hit_probability_gd_novice  = 0.80
hit_probability_gd_stalker = 0.80
hit_probability_gd_veteran = 0.80
hit_probability_gd_master  = 0.80
```

Текущая реализация `CWeapon::hit_probability()` всегда возвращает элемент `gd_novice`, хотя при загрузке оружия читаются все четыре значения. Следовательно, в этой ветке фактически действует `hit_probability_gd_novice` независимо от выбранной сложности.

Вероятность интерполируется от `1,0` в точке выстрела до значения оружия на дистанции `hit_probability_max_dist`. В текущем `gamedata/configs/weapons/weapons.ltx` эта дистанция равна `3 м`; дальше используется полное значение оружия. Затем результат умножается на `hit_probability_factor` конкретного персонажа. Если тег отсутствует, коэффициент равен `1,0`; в текущих XML-профилях явных тегов `hit_probability_factor` нет.

Этот фильтр:

- действует только при попадании по актору в одиночной игре;
- не меняет траекторию и группирование пуль на поверхности;
- не меняет попадания НПС по другим НПС;
- может сделать НПС менее опасным для игрока, даже если `disp_*` не изменялись.

Поэтому для оценки именно углового разброса нельзя полагаться только на долю урона, полученного игроком.

## Что настраивать для разных задач

### Изменить меткость всех обычных НПС

Меняйте восемь `disp_*` в секции `[stalker]` файла `m_stalker.ltx`. Сохраняйте логичное соотношение состояний:

```text
бег менее точен, чем ходьба;
ходьба менее точна, чем неподвижная стрельба;
стрельба стоя менее точна, чем стрельба пригнувшись.
```

Для равномерного изменения удобнее сначала умножить все восемь значений на один коэффициент:

```text
0,75 — вклад НПС в разброс меньше на 25%;
1,25 — вклад НПС в разброс больше на 25%.
```

Это масштабирует только `D_npc`. Базовый разброс оружия останется прежним, поэтому полный результат не изменится ровно на тот же процент.

### Изменить меткость отдельного типа НПС

Переопределяйте `disp_*` в собственной секции сущности, наследующей `[stalker]`. Изменение общей секции затрагивает также `[stalker_monolith]`, потому что она наследуется от `[stalker]` и не переопределяет разброс. Зомбированные используют собственные значения из `[stalker_zombied]`.

```ini
[example_sharpshooter]:stalker
disp_walk_stand        = 2.0
disp_walk_crouch       = 1.5
disp_run_stand         = 4.0
disp_run_crouch        = 3.0
disp_stand_stand       = 1.5
disp_stand_crouch      = 1.0
disp_stand_stand_zoom  = 0.75
disp_stand_crouch_zoom = 0.50
```

Секция должна реально использоваться как секция объекта. Профиль `specific_character` сам по себе не подменяет `cNameSect()` НПС.

### Изменить точность конкретного оружия у всех владельцев

Меняйте `fire_dispersion_base`, `fire_dispersion_condition_factor`, коэффициенты глушителя или `k_disp` патрона. Эти изменения действуют не только на НПС, поэтому их следует балансировать отдельно от `m_stalker.ltx`.

### Изменить только опасность НПС для игрока

Меняйте `hit_probability_gd_novice` в секциях оружия, учитывая текущее жёстко выбранное значение сложности. Это не является заменой настройки разброса: пули продолжат лететь по прежним траекториям, но часть геометрических попаданий по актору не будет засчитана.

### Изменить плотность огня

Используйте `[fire_queue_params]`: размеры очередей и интервалы между ними. Более длинная очередь повышает число выпущенных пуль и может увеличить фактическое число попаданий, но разброс каждой обычной пули по-прежнему рассчитывается через формулу выше.

## Рекомендуемый порядок настройки

1. Зафиксируйте оружие, патрон, состояние оружия, ранг НПС, дистанцию и положение тела.
2. Сначала настройте `disp_*`, не меняя одновременно оружие, вероятность попадания и очереди.
3. Проверьте ходьбу, бег, неподвижную стрельбу стоя и пригнувшись отдельно.
4. Проверьте несколько рангов. Для текущих профилей особенно полезны `0`, `50` и `100`.
5. Отдельно настройте `fire_dispersion_base` оружия и `k_disp` боеприпасов.
6. Только после группирования пуль подберите `hit_probability_gd_novice` и параметры очередей под желаемую опасность для игрока.
7. Полностью перезапустите игру перед итоговой проверкой. Коэффициенты `[ranks_properties]` кэшируются статическими переменными при первой инициализации НПС.

Автоматическая проверка конфигов и сборка подтверждают только чтение и связность параметров. Итоговую меткость, темп боя и ощущение справедливости необходимо отдельно принять в игре.

## Где это реализовано

- `gamedata/configs/creatures/m_stalker.ltx` — восемь базовых параметров `disp_*` и секция очередей.
- `gamedata/configs/creatures/game_relations.ltx` — коэффициенты разброса по рангу.
- `src/xrGame/ai/stalker/ai_stalker.cpp` — загрузка параметров и расчёт коэффициента ранга.
- `src/xrGame/ai/stalker/ai_stalker_fire.cpp` — выбор `disp_*` по состоянию НПС.
- `src/xrGame/WeaponDispersion.cpp` — сложение разброса оружия и стрелка.
- `src/xrGame/WeaponFire.cpp` — генерация случайного направления пули.
- `src/xrGame/Level_bullet_manager_firetrace.cpp` — дополнительная проверка вероятности попадания по актору.
